# Анализ работы JVM для кода JvmComprehension

## 1. Загрузка классов (ClassLoader)

Перед выполнением кода JVM загружает необходимые классы:
- `JvmComprehension` (наш класс)
- `Object` (родительский класс для всех объектов)
- `Integer` (класс-обертка для `int`)
- `System` (из стандартной библиотеки Java)
- `String` (для работы со строками)

Загрузка происходит с помощью ClassLoader'ов:
1. **Bootstrap ClassLoader** – загружает основные классы Java (например, `Object`, `System`).
2. **Platform ClassLoader** (ранее `Extension ClassLoader`) – загружает классы расширений.
3. **Application ClassLoader** – загружает наш класс `JvmComprehension` и другие пользовательские классы.

После загрузки информация о классах (метаданные, методы, поля) хранится в **Metaspace**

## 2. Выполнение метода main()

При запуске программы создается поток (`main`), и для него выделяется **стэк** (stack). В стэке создается **фрейм** (кадр) для метода `main()`.

### Строка 1: `int i = 1;`
- В фрейме `main()` создается примитивная переменная `i` со значением `1`.
- Примитивы хранятся **непосредственно в стэке**.

### Строка 2: `Object o = new Object();`
- `new Object()` создает объект в **куче (heap)**.
- В стэке (в фрейме `main()`) создается ссылка `o`, которая указывает на этот объект в куче.

### Строка 3: `Integer ii = 2;`
- `Integer` – это класс-обертка, но благодаря **автоупаковке** (autoboxing) `2` преобразуется в `Integer`.
- Объект `Integer` создается в **куче**, а ссылка `ii` хранится в стэке.

### Строка 4: `printAll(o, i, ii);`
- Вызов метода `printAll()` создает **новый фрейм** в стэке поверх фрейма `main()`.
- В этот фрейм передаются:
    - ссылка на объект `o` (из кучи),
    - копия значения `i` (так как `i` – примитив),
    - ссылка на объект `ii` (из кучи).

### Строка 5 (в методе `printAll`): `Integer uselessVar = 700;`
- Создается новый объект `Integer` в **куче** со значением `700`.
- В фрейме `printAll()` появляется ссылка `uselessVar` на этот объект.

### Строка 6: `System.out.println(o.toString() + i + ii);`
- Происходит несколько действий:
    1. Вызов `o.toString()` – создается новый объект `String` в куче (результат `toString()`).
    2. Значение `i` преобразуется в строку (новый объект в куче).
    3. `ii.toString()` – еще один `String` в куче.
    4. Все строки конкатенируются (еще один объект `String`).
    5. Результат передается в `System.out.println()`.
- В куче появляется несколько временных объектов `String`.

### Строка 7: `System.out.println("finished");`
- Строковый литерал `"finished"` хранится в **String Pool** (в куче).
- `System.out.println()` выводит его.

## 3. Завершение работы и сборка мусора (Garbage Collection)

- После завершения метода `printAll()` его фрейм удаляется из стэка.
    - Ссылка `uselessVar` (на `Integer 700`) больше не доступна → объект `700` становится **мусором**.
- После завершения `main()` его фрейм также удаляется.
    - Объекты `Object`, `Integer 2` и `Integer 700` больше не имеют ссылок и могут быть удалены **сборщиком мусора (GC)**.
- Строки из **String Pool** (`"finished"`) могут остаться, так как они могут переиспользоваться.
